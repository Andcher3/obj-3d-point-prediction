## 2. 三个研究方向的直白理解

### 方向一：手机视频场景下的行为识别

这个方向关心的是：

> 只看手机里的 IMU 信号，能不能判断人在做什么、手机镜头在怎么运动，以及接下来动作是否会发生切换？

这里的 IMU 主要包括：

- 加速度计 accelerometer
- 陀螺仪 gyroscope

这个方向更偏“动作语义理解”。它不只是判断人在走路、站立、坐下，还要进一步理解手机本身的运镜行为，比如平移、旋转、启停等。

可以先把它理解成：

```text
IMU 时间序列 -> 当前人体行为 + 当前手机运动方式 + 未来切换趋势
```

关键词：

- 人体行为识别
- 运镜行为识别
- 多通道时间序列建模
- 组合行为理解
- 状态切换预测
- 移动端实时部署

### 方向二：面向手机 OIS 的姿态预测与冲击预警

这个方向关心的是：

> 根据过去一小段时间的 IMU 信号，能不能预测手机接下来几十毫秒会怎么动，以及是否即将发生冲击？

OIS 是 Optical Image Stabilization，也就是光学防抖。传统 OIS 往往是“发生运动后再补偿”，因此会存在滞后。这个课题希望通过预测，让系统提前知道未来短时间内的姿态变化或冲击风险。

可以先把它理解成：

```text
过去 L ms 的 IMU -> 未来 N ms 的姿态/IMU 变化 + 冲击概率 + 冲击到达时间
```

关键词：

- 短时序列预测
- 姿态回归
- gyro/acc 预测
- 冲击事件检测
- 到达时间回归
- 流式推理
- 模型压缩与量化

### 方向三：退化视频的高质量重建

这个方向关心的是：

> 手机拍出来的视频如果模糊、抖动、闪烁、不连贯，能不能先定位问题，再用合适算法把视频修复得更清晰、更连贯？

这个方向和前两个相比，技术栈明显不同。它更偏视频重建和视觉算法，而不是单纯的 IMU 时间序列建模。

可以先把它理解成：

```text
退化视频 + 可能的传感器信息 -> 退化类型/区间 -> 重建后的视频
```

关键词：

- 视频退化检测
- 视频去模糊
- 视频帧插值
- 视觉里程计
- 3D Gaussian Splatting
- 端侧轻量化部署

目前优先级：先放一放，等前两个 IMU 方向建立基本理解后再系统展开。

## 3. 为什么先学前两个方向

前两个方向表面任务不同，但底层都围绕同一件事：

```text
手机 IMU 时间序列建模
```

它们共同需要理解：

- 加速度计和陀螺仪信号
- 三轴数据 x/y/z
- 滑动时间窗
- 时间序列分类
- 时间序列回归
- 事件检测
- 移动端低延迟推理

区别在于：

- 方向一更像“识别”：这段运动代表什么行为？
- 方向二更像“预测”：未来短时间会怎么动？会不会发生冲击？

所以比较稳妥的学习顺序是：

```text
先看懂 IMU 波形
-> 再做人类活动识别
-> 再做状态切换预测
-> 再做短时未来预测和冲击预警
```

## 4. 当前阶段：UCI HAR 数据集入门

当前已经解压的数据集在：

```text
HAR/UCI HAR Dataset/
```

原始压缩包还在：

```text
human+activity+recognition+using+smartphones.zip
```

这个数据集的作用是帮助你建立对手机 IMU 数据的直觉。它不是最终课题数据集，但非常适合用来入门。

### 数据集基本信息

UCI HAR 数据集来自 30 名受试者。每个人把手机戴在腰部，完成 6 类日常动作。手机采集加速度计和陀螺仪信号。

几个关键数字：

```text
采样率：50 Hz
窗口长度：2.56 秒
每个窗口采样点数：128
活动类别数：6
受试者人数：30
```

因为：

```text
128 / 50 = 2.56 秒
```

所以每一行样本都可以理解成一段 2.56 秒的动作片段。

### 6 类动作标签

```text
1 WALKING
2 WALKING_UPSTAIRS
3 WALKING_DOWNSTAIRS
4 SITTING
5 STANDING
6 LAYING
```

直观理解：

- `WALKING`：走路
- `WALKING_UPSTAIRS`：上楼
- `WALKING_DOWNSTAIRS`：下楼
- `SITTING`：坐着
- `STANDING`：站着
- `LAYING`：躺着

前三类通常更有周期性波动；后三类通常更平稳。

## 5. UCI HAR 目录结构怎么理解

### train 和 test

数据集分成：

```text
train/
test/
```

注意：这里的 `test` 是官方测试集，不建议直接把它叫作验证集。如果后面需要 validation，最好从 `train` 里再划分一部分出来。

当前本地数据规模是：

```text
train: 7352 个窗口样本
test : 2947 个窗口样本
```

### X_train.txt / X_test.txt

这两个文件是已经提取好的特征表。

以 `X_train.txt` 为例：

```text
7352 行 x 561 列
```

含义：

- 每一行：一个 2.56 秒时间窗，也就是一个样本。
- 每一列：一个统计特征或频域特征。

这些特征是从 IMU 信号中加工出来的，例如：

- 均值
- 标准差
- 最大值
- 最小值
- 能量
- 频域特征
- 相关系数

适合用来做传统机器学习 baseline，例如：

- SVM
- Random Forest
- XGBoost
- Logistic Regression

### y_train.txt / y_test.txt

这是动作标签。

以 `y_train.txt` 为例：

```text
7352 行 x 1 列
```

它和 `X_train.txt` 按行一一对应：

```text
X_train 第 i 行 -> y_train 第 i 行
```

意思是：第 i 个时间窗对应的真实动作类别是什么。

### subject_train.txt / subject_test.txt

这是受试者编号。

以 `subject_train.txt` 为例：

```text
7352 行 x 1 列
```

它也和 `X_train.txt` 按行一一对应：

```text
X_train 第 i 行 -> subject_train 第 i 行
```

意思是：第 i 个时间窗来自哪一位受试者。

这个文件后面很重要，因为研究中经常会关心模型是否能泛化到“没见过的人”。

## 6. Inertial Signals 文件夹最重要

当前阶段最应该关注的是：

```text
train/Inertial Signals/
test/Inertial Signals/
```

这里放的是更接近原始 IMU 的时间序列数据。

每个文件都是类似这样的形状：

```text
样本数 行 x 128 列
```

以训练集为例：

```text
body_acc_x_train.txt: 7352 行 x 128 列
```

含义：

- 每一行：一个时间窗样本。
- 每一列：这个时间窗内部的一个采样点。
- 128 列：表示 2.56 秒内的 128 个连续采样值。

### 9 个通道分别是什么

`Inertial Signals` 中有 9 路信号：

```text
total_acc_x
total_acc_y
total_acc_z
body_acc_x
body_acc_y
body_acc_z
body_gyro_x
body_gyro_y
body_gyro_z
```

可以分成三组。

### total_acc_x/y/z

这是手机加速度计测到的三轴总加速度，单位是 `g`。

它包含：

```text
人体运动带来的加速度 + 重力分量
```

所以它不是纯粹的人体运动信号，而是混合了重力影响。

### body_acc_x/y/z

这是从总加速度里去掉重力成分后得到的身体运动加速度，单位也是 `g`。

它更直接反映人体运动本身，所以做人类活动识别时非常重要。

可以粗略理解成：

```text
body_acc = total_acc - gravity_acc
```

### body_gyro_x/y/z

这是陀螺仪测到的三轴角速度，单位是 `rad/s`。

它描述的是手机绕 x/y/z 三个轴旋转得有多快。

对于识别手机姿态变化、转动、运镜行为，陀螺仪信号尤其重要。

## 7. 一个样本应该怎么组织

对于同一个样本编号 i，可以从 9 个文件里各取第 i 行。

每一行都有 128 个数。

所以一个样本可以组织成：

```text
9 x 128
```

也就是：

```text
9 个通道，每个通道 128 个时间点
```

在深度学习里，通常也会转成：

```text
128 x 9
```

也就是：

```text
128 个时间点，每个时间点 9 个通道值
```

两种表示本质一样，只是维度顺序不同。

## 12. PPT / 幻灯片制作规则

后续凡是制作 PPT、组会汇报、论文讲解幻灯片或类似材料，都必须遵守以下规则：

- 每一页幻灯片都必须使用 image gen skill / 图像生成工具生成整页图像，再插入 PPT。除非用户明确要求，否则不要主要用可编辑文本框拼 PPT。
- 主要内容页面应以当前已有 PPT 的风格作为模板，保持前后一致。
- 整份 PPT 要有足够信息量，排版不能松散，也不能臃肿。
- 中英文字体一律以微软雅黑 / Microsoft YaHei 为主。
- 矢量图只能作为辅助理解使用，禁止滥用。如果观众只看矢量图、不看文字时无法联想到对应含义，就不要添加该矢量图。
- 插图应优先使用实际例子图、论文图风格的模型结构图、数据流程图、实验结果表格等真正服务内容的图。
- 不要在 PPT 中出现“真实场景示例”“学术风格插图”这类与实际内容无关的标题。标题或说明应直接描述图中内容本身。
- 不要每一页都在底部放总结气泡。只有当该页确实需要一句话收束时才加入总结。
- 不要出现页数标记，除非用户明确要求。
- 不要把某个区域在 PPT 中的功能定位直接写成标题。例如不要把“评价指标解释”直接写成气泡标题，而应通过排版、分组、字号、颜色或更具体的内容标题表达其功能。
