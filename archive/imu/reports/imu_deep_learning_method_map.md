# IMU/HAR 深度学习方法地图

本文用于把当前 UCI HAR 的信号观察，过渡到后续真正要学习和实现的深度学习方法。

当前输入形式已经明确：

```text
X_train_raw: 7352 x 128 x 9
```

含义：

- `7352`：训练样本数
- `128`：每个 2.56 秒窗口内的时间点
- `9`：IMU 通道数

深度学习模型的核心变化是：

```text
不再手工为每个窗口设计全部特征，而是让模型从 128 x 9 的时序片段中自动学习有用模式。
```

## 1. 为什么现在可以进入深度学习

前面做的波形观察不是绕远路，而是在回答这些问题：

- 哪些类别靠波动强度就能初步区分？
- 哪些类别的曲线形状很像？
- 哪些差异来自周期运动？
- 哪些差异来自重力方向？

这些观察会帮助理解模型到底在学什么。

现在我们已经知道：

- 动态/静态比较容易区分。
- 上楼、下楼、走路都属于周期步态，曲线形状相似。
- 坐、站、躺在 `body_acc/body_gyro` 中很平滑，差异更多来自 `total_acc` 的重力方向。

因此下一步进入深度模型是合理的。

## 2. 第一类方法：1D CNN

### 直观理解

1D CNN 是处理 IMU/HAR 最自然的第一个深度学习 baseline。

它把时间维度当成一条序列，在局部时间片段上滑动卷积核：

```text
局部时间片段 -> 局部运动模式 -> 更高层运动特征 -> 动作分类
```

对于 UCI HAR，一个输入样本可以看作：

```text
128 个时间点，每个时间点 9 个通道
```

1D CNN 会学习类似这些局部模式：

- 某个轴上是否有周期波峰
- 三轴之间是否同步变化
- 一小段时间内加速度是否突然增强
- 陀螺仪是否出现规律摆动

### 优点

- 训练快。
- 结构简单。
- 很适合作为第一个深度学习 baseline。
- 对端侧部署友好。
- 能自然处理多通道 IMU。

### 局限

- 主要看局部模式。
- 如果行为依赖更长时间上下文，普通 CNN 可能不够。

### 在本项目中的位置

这是下一步最应该先实现的模型。

建议目标：

```text
UCI HAR 9 通道原始时序 -> 1D CNN -> 6 类动作分类
```

## 3. 第二类方法：LSTM / GRU

### 直观理解

LSTM 和 GRU 是经典循环神经网络，用来处理序列。

它们按时间顺序读入 IMU：

```text
t1 -> t2 -> t3 -> ... -> t128
```

理论上，它们更擅长建模“前后依赖”。

### 优点

- 直观上适合时间序列。
- 能捕捉一定的时间上下文。
- 对后续“行为状态切换预测”有启发意义。

### 局限

- 训练速度通常慢于 CNN。
- 并行性较差。
- 在很多实际时间序列任务中，普通 LSTM/GRU 不一定比 CNN 更强。

### 在本项目中的位置

不建议第一个做，但建议作为第二或第三个 baseline。

可以比较：

```text
1D CNN vs GRU vs LSTM
```

## 4. 第三类方法：DeepConvLSTM

### 直观理解

DeepConvLSTM 是 HAR/可穿戴传感器领域非常经典的深度学习结构。

它的思想是：

```text
CNN 先提取局部运动特征
LSTM 再建模时间上的演化关系
```

也就是：

```text
IMU 时序 -> 卷积特征 -> 循环序列建模 -> 动作分类
```

### 为什么重要

它是从“简单深度模型”走向“领域经典模型”的关键一步。

对于 UCI HAR，它可以被理解为：

- CNN 学习局部步态片段。
- LSTM 学习这些局部片段如何在窗口内排列。

### 在本项目中的位置

建议在完成 1D CNN baseline 后实现。

## 5. 第四类方法：TCN

### 直观理解

TCN 是 Temporal Convolutional Network，也就是时间卷积网络。

它使用因果卷积、膨胀卷积和残差结构，让 CNN 也能看到更长的时间范围。

它的核心优势是：

```text
像 CNN 一样并行高效，又能覆盖较长历史。
```

### 为什么适合本项目

TCN 不只适合方向一的人体行为识别，也非常适合方向二的短时预测：

```text
过去 L ms IMU -> 未来 N ms IMU/姿态
```

因为方向二强调：

- 低延迟
- 流式推理
- 短时预测
- 移动端可部署

这些都和 TCN 的特点比较契合。

### 在本项目中的位置

建议作为较强 baseline：

```text
1D CNN -> DeepConvLSTM -> TCN
```

## 6. 第五类方法：InceptionTime / ResNet 类时间序列分类模型

### 直观理解

InceptionTime 是时间序列分类领域的强 CNN 系列方法。

它使用不同长度的卷积核同时看不同尺度的时间模式：

```text
短卷积核：看局部尖峰和短节奏
长卷积核：看更长周期和趋势
```

这对 IMU 很自然，因为动作可能同时包含：

- 短时冲击
- 步态周期
- 整个窗口的趋势

### 在本项目中的位置

它适合作为“强分类模型”参考，但不建议第一个实现。

推荐顺序：

```text
先 1D CNN
再 TCN / DeepConvLSTM
最后看 InceptionTime 类强模型
```

## 7. 第六类方法：Transformer / PatchTST 类模型

### 直观理解

Transformer 使用注意力机制，让模型自己学习时间点之间的关系。

PatchTST 这类模型把时间序列切成 patch：

```text
原始时间点 -> 小片段 patch -> token -> Transformer
```

这类方法在长时间序列预测、自监督表示学习中很常见。

### 优点

- 能建模长距离依赖。
- 适合大数据和预训练。
- 适合多任务、迁移学习、自监督学习。

### 局限

- 对小数据集不一定划算。
- 计算量可能较大。
- 对移动端实时部署不一定友好。
- 对 UCI HAR 这种窗口只有 128 点的小数据，未必第一时间优于 CNN/TCN。

### 在本项目中的位置

它更适合后续研究拓展，而不是当前第一个 baseline。

可以在方向二中重点关注：

```text
短时 IMU 预测
自监督预训练
跨场景迁移
```

## 8. 第七类方向：自监督学习

### 直观理解

自监督学习不依赖人工标签，而是让模型通过设计任务学习 IMU 表示。

常见任务包括：

- 遮住一段 IMU，让模型恢复。
- 判断两个窗口是否来自相邻时间段。
- 对同一个窗口做扰动，让模型学到稳定表示。
- 用未来预测作为预训练任务。

### 为什么重要

真实课题中，手机 IMU 数据可能很多，但精确标注很贵。

因此自监督学习可能会比单纯监督分类更贴近未来研究。

### 在本项目中的位置

当前先了解即可，不急着实现。

## 9. 和两个课题的对应关系

### 对课题一：行为识别与状态切换

推荐路线：

```text
1D CNN 分类
-> DeepConvLSTM / TCN 分类
-> 当前行为 + 下一状态/切换概率 多任务模型
-> 自监督预训练或 Transformer 表示学习
```

课题一最终不只是分类，而是：

```text
当前行为是什么？
是否正在切换？
接下来是否会继续？
```

所以后面会从单窗口分类扩展到连续窗口序列建模。

### 对课题二：短时姿态预测与冲击预警

推荐路线：

```text
TCN / GRU 短时预测
-> seq2seq 回归未来 IMU
-> 冲击检测 + 到达时间回归 + 强度分类
-> 轻量化与流式推理
```

课题二更偏预测，不只是分类。

因此后续会关注：

- MAE / RMSE
- 预测 horizon
- 提前量
- 延迟
- 端侧部署

## 10. 当前最推荐的下一步

现在不要直接追 Transformer，也不要直接写复杂论文模型。

最推荐下一步：

```text
实现一个 1D CNN baseline，用 9 通道原始 IMU 时序做 6 类动作分类。
```

原因：

- 它是深度学习路线的最小闭环。
- 它能验证我们整理的 `7352 x 128 x 9` 数据是否真正可用于模型。
- 它能作为后续 DeepConvLSTM、TCN、Transformer 的比较基线。

建议第一版实验目标：

```text
输入：128 x 9
模型：Conv1D -> Conv1D -> GlobalAveragePooling -> Dense
输出：6 类动作
指标：accuracy、macro F1、confusion matrix
```

## 11. 目前环境提醒

当前 `HAR` conda 环境中已验证可用：

```text
numpy 1.24.3
```

但 PyTorch 尚不可用；TensorFlow 在该环境中检测到用户级残留包，但实际导入缺依赖，不应作为可靠框架。

本机 `jupyter` conda 环境中检测到 PyTorch 可用。后续有两种选择：

1. 先用 `jupyter` 环境快速跑通 PyTorch 版 1D CNN baseline。
2. 或者先把 PyTorch 正式装入 `HAR` 环境，再保持所有 HAR 工作都在 `HAR` 中。

考虑到本机网络/代理对安装包不稳定，建议优先使用已有可用环境快速跑通第一个 baseline。
