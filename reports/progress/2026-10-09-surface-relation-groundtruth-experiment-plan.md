# 三维真值数据与下一阶段关系预测实验建议

## 完成内容与权限边界

用户询问选定 UniQuery4R 教师后如何进一步验证方法、是否存在自带三维点轨迹真值的数据。本轮核查官方项目、作者仓库及本地历史记录，制定实验建议。未开启 GPU、连接服务器、下载大型数据、修改模型或运行训练。

AI辅助完成检索和计划整理。以下参数为本轮建议，未覆盖既有实验协议。

## 数据来源

### Kubric / MOVi 与 TAPIP3D 作者发布的 MOVi-F

- [Kubric MOVi 官方说明](https://github.com/google-research/kubric/blob/main/challenges/movi/README.md)：仿真多物体视频，实例 mask、深度、物体坐标、物体位姿和相机参数；普通 MOVi 文件不能笼统描述为直接包含现成三维点轨迹 NPZ。可利用物体固定坐标和位姿生成轨迹。
- [TAPIP3D 官方数据说明](https://github.com/zbw001/TAPIP3D/blob/main/DATASET.md) 指向作者提供的 [MOVi-F 三维轨迹训练数据](https://huggingface.co/datasets/zbww/tapip3d-kubric)。数据卡明确说明有三维点轨迹真值，适合优先检查文件接口。
- 普通 MOVi 主要是刚体场景；在该子集上成功只能支持此运动范围内的可行性，不把刚体假设写入方法。
- 公开训练包约160GB（查阅时数据卡信息），不需全量下载。应按独立场景选取必要子集、逐场景处理，保持用户本地空间约束。
- 三维轨迹包未证明包含完整表面网格。若做真实表面路径距离对照，需要另核查实例资产网格、顶点连通及其与 query 的对应关系。

### PointOdyssey v1.2

- [官方项目](https://pointodyssey.com/) 和 [作者仓库](https://github.com/y-zheng18/point_odyssey) 明确提供 RGB、深度、实例分割、相机参数及二维/三维点轨迹真值。作者 v1.2 说明修复了部分 mask 和深度问题，因此使用这一版而非默认为所有版本都无误。
- 仿真标签不依赖 UniQuery4R 的预测，适合受控方法训练和独立评估。
- 包含大量人/动物场景，必须只选明确的非人非动物目标物体；物体子集规模需实际审计，不承诺159段全部可用。
- 本项目09-26已下载过两个官方样本并验证真值投影，见 `2026-09-26-pointodyssey-interface-data-preflight.md`；当时测试目标含人物/机器人，本轮不将这些目标作为新的合格物体主实验。可复用读取代码和坐标审计经验，另选目标。
- 当时真值与 RGB-only 估计观测几何存在偏差；这不使仿真真值变成教师伪标签。需要区分已知标签坐标转换与输入几何误差，不能通过逐点对齐修改真值掩盖后者。

### TAPVid-3D（真实视频）

- [官方项目](https://tapvid3d.github.io/) 和 [官方代码说明](https://github.com/google-deepmind/tapnet/blob/main/tapnet/tapvid3d/README.md) 提供真实视频三维点轨迹标注。
- [论文第3节](https://arxiv.org/html/2407.05921v1#S3) 说明 ADT 基于数字孪生几何/物体位姿、DriveTrack 基于 LiDAR/物体框跟踪、Panoptic 基于动态三维重建。存在数字模型与实拍错位、传感器噪声及重建误差。
- 它能提供独立于本次 UniQuery4R 的标注，不能称为无误差真值。优先 ADT 的目标物体或 DriveTrack 的车辆，不使用人体为目标的 Panoptic 子集。
- 定位是独立真实视频验证；按官方划分与来源授权使用，不将整个评测集拿去训练。

## 研究问题与阶段顺序

研究问题：给定指定物体的观测 RGB，显式的跨点关系和观测表面关系，是否提高未来三维点轨迹的预测准确性？

### G0：真值接口与教师误差标定

先选10–20个独立仿真物体场景检查真实轨迹、query身份、相机投影、时间戳和目标实例。已有合成梯度/零修正检查无需重做。

同一批 RGB 与相同 query 让 UniQuery4R 输出完整输入轨迹，再与数据集真值比较。报告观测和未来点位误差、三维边向量误差、点间长度差异、遮挡情况及不同运动类别。该步骤量化教师偏差，不根据“7帧与22帧彼此一致”推断真实准确性。

坐标处理：GT变换到最后观测相机坐标；模型输出使用其真实归一化参数反归一化。尺度不确定时只用观测期估计一个整体比例，固定用于未来，原始与尺度调整结果同时报告。不能使用未来真值拟合测试输出，不能逐点平移GT直到和估计t0完全重合。RGB-only观测几何的误差可以是模型应面对的输入误差，不再自动作为拒绝GT标签的理由。

### G1：真值监督下的跨点关系对照

建议从更适合物体目标的Kubric/MOVi-F取独立场景，初始训练100、验证20、测试40。按原始场景划分，同一场景所有目标与时间窗属于同一划分；初轮每场景一个目标、一个固定窗口。划分应遵守原始发布的测试边界；若选用只有train分区的转换包，自建划分须如实命名为研究划分，不声称官方测试集。

这一规模是可行性试验起点，不是统计功效保证。必要扩展使用独立新场景，不把多个query、seed或同场景窗口当成新增独立样本。测试结果不能用来反复选模型。

优先沿用48个query、7帧观测/15帧未来，但必须根据数据实际fps匹配模型时间槽位；普通MOVi默认12fps不能直接假称15fps。可通过合适原生时间配置生成仿真数据，或在模型明确支持时适配时间条件。具体帧协议在输入审计后确认，不能仅改播放帧率。

对照：

| 组别 | 结构 | 目的 |
|---|---|---|
| A | 原始MotionForesight | 无新增模块参照 |
| B | 等容量逐点解码器，无跨点通信 | 控制新增参数、观测特征及额外训练影响 |
| C | 联合关系解码器，简单固定邻接 | 单独检验跨点通信作用 |

B/C共享观测历史、物体共享状态、时间处理、训练步数、优化器和损失，包括同一评估边集上的关系损失。差别限定为跨点通信，避免把额外监督与结构改变混在一起。第一阶段冻结MotionForesight、训练新增解码器；采用3个初始化种子，按视频先汇总再比较。

主实验仅输入观测RGB、目标mask及query，观测三维特征由仅观测输入估计；不将GT未来位姿/深度/相机输入预测模型。GT只作标签、坐标定义或明确标记的额外oracle诊断。

### G2：表面距离的增量作用

在相同架构及预算下比较 C 与 D（加入观测表面邻接/路径距离）。尽量匹配图密度和特征维度；使用固定的共同评估点对，不只在各自构图边上打分。

进一步分开：

- D-oracle：观测期仿真真实表面关系，明确是诊断，超出RGB-only输入，不作为正式方法结果。
- D-estimated：仅由观测RGB估计的可见表面关系，作为主方法。

如果暂时无法取得可靠资产网格，则G2暂不声称测试真实表面距离；可用GT深度构造可见表面作为有限oracle诊断，并明确它不是完整表面测地。3D点轨迹真值本身不自动给出表面拓扑或路径距离。

### G3：真值标签与UniQuery4R标签训练对照

在同一组训练视频、同一输入、同一架构和预算下，分别用GT与UniQuery4R伪标签训练；两者都在同一批独立GT测试视频上评价。

由此区分：干净标签下方法表现、教师监督噪声引起的变化。评价必须仍以GT为依据；不能以“更接近UniQuery4R”替代“更接近真实轨迹”。

之后在新增、独立的真实物体视频上检查迁移。现有四段DAVIS用于接口与人工观察，已经参与设计讨论，不作为唯一正式测试集，也不通过增加其裁剪数量伪增独立视频数。

## 评价与决策建议

- 绝对轨迹平均误差与终点误差。
- 三维相对位置向量误差；去除整体平移后的点位误差，说明点集合结构是否改善。
- 在统一点对上的长度误差；按转动、遮挡、接触等情况分别报告。
- 可见/遮挡点分开。有效GT三维位置即使被遮挡也可以评估；不能仅保留易点。
- 不将平滑或固定边长作为成功指标，不强迫形变目标刚体化。

建议预先登记5%为最小关注改善量（工程判断，不是文献公认门槛）：C要优于A和B的结构误差，并且绝对轨迹误差不出现明确恶化；D的增益进一步相对C检验。以独立场景配对bootstrap估计不确定性，不能把三种子的结果当成三倍视频数量。若区间横跨有用改善与恶化，不宣布方法已证明或已否定；按训练/验证学习曲线和事先扩展规则补充独立数据，避免依据同一测试集调参。

明确负结果可支持：在训练充分、数据接口正确的范围内，该具体冻结输出端架构没有实用收益。不能外推为所有关系建模无效。若G1成功而G2无增益，保留通信价值、重新审视表面距离组件；若GT训练成功而伪标签训练失败，教师监督是主要候选限制之一。即使G0发现教师误差，也不预先宣布G3必然失败。
