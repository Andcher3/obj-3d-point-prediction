# 当前两阶段方法的低成本可行性测试

日期：2026-09-16

## 目标

当前版本为“多未来 narration 第一阶段 + 文本条件确定性 MotionForesight 第二阶段”。近期测试应分别验证数据监督、未来语义生成、文本到轨迹的条件通路和阶段接口；暂不引入随机视觉 mask、轨迹 flow 或概率校准。

## 测试 0：数据与时间接口审计

从候选数据中抽取少量样本，联合可视化观察片段、未来窗口、目标物体、future narration、query points 和离线三维伪轨迹。检查 narration 是否描述指定目标在同一未来窗口内的事件，目标在观察段是否可指定，轨迹伪标签是否有效，以及任何未来帧是否误入预测输入。

这是进入训练前的必要测试。若有效样本比例过低，应先修改数据构造或任务时间协议。

## 测试 1：第一阶段冻结先验与多候选 probe

先不训练完整 ModeSeq。对同一观察视频和目标，使用候选 VLM 生成多条 narration，比较：

- greedy 单输出；
- 独立 token sampling；
- 将前序候选反馈给后续生成，并用双向蕴含去重的轻量顺序版本；
- 打乱视频或去掉目标指定的负对照。

报告 GT 语义匹配的 top-1 与 oracle@S、双向蕴含聚类后的事件模式数、重复率、目标相关性和人工合理性。第一阶段只做事件级评价，不使用三维轨迹评价。若顺序版本只增加措辞差异或明显降低合理性，则 ModeSeq 式机制尚未获得支持。

## 测试 2：小样本过拟合与条件通路单元测试

分别让第一阶段 LoRA 和第二阶段文本条件 MotionForesight 在单批或极小数据集上过拟合，确认损失下降、参数确实更新、文本 context 进入 cross-attention，并能复现训练目标。

对第二阶段增加一个受控路由测试：复制同一视觉输入，为两条明确不同的文本条件配置两个可区分的合成轨迹目标。该测试只判断架构能否利用文本选择输出，不能证明真实语义或物理泛化。若此测试失败，应先修正文本编码、cross-attention LoRA 或梯度路径。

## 测试 3：真实数据文本利用消融

在相同训练预算下比较：

1. 原始无文本 MotionForesight；
2. 正确 future narration；
3. 空文本；
4. batch 内随机置换 narration。

在独立验证样本上报告 ADE/FDE、端点误差、可见性和局部连续性。对同一视频再做正确、空、置换和冲突文本推理，固定其他输入，测量宏观轨迹变化。

正确文本优于空文本和置换文本，才说明文本提供了可泛化信息。冲突文本使输出发生变化只证明敏感性；没有反事实三维真值时，不能证明该轨迹正确。

## 测试 4：端到端接口分解

固定第二阶段，比较四种文本来源：

```text
GT future narration
第一阶段 top-1 narration
第一阶段候选中的 oracle narration（只作诊断）
空文本
```

该测试的轨迹指标用于评价系统接口和第二阶段，不作为第一阶段的独立评价门槛。结果可以定位瓶颈：

- GT 文本不优于空文本：第二阶段未有效利用文本；
- GT 文本有效，预测文本无效：第一阶段质量或阶段间文本分布存在问题；
- oracle 候选有效而 top-1 无效：候选覆盖存在，但排序或置信度需要改进；
- top-1 已接近 GT：当前确定性两阶段版本具有继续扩展的依据。

## 推荐顺序

优先执行测试 0、测试 1 和测试 2。通过后再训练测试 3；测试 4 放在两个阶段分别通过后。第一轮不需要验证同一 narration 内轨迹多样性、概率校准、随机视觉 mask 或 flow。
