# F2 失败原因与点间关系方案重设计

- 日期：2026-09-26
- 范围：解释 Relation Head 使用点间关系后仍劣于 baseline 的原因，并提出下一版最小改法。
- 状态：ANALYZED；未运行新训练实验。

## 已有证据支持的原因

1. **关系修正被无条件应用。**  
   原始 F2、history/shared/safe 版本均在留出视频上整体劣于 baseline。训练折的门控几乎总选 `1.0`，说明验证段没有学会识别“当前 baseline 是否真的需要修正”。已准确的视频被继续修改，产生过修正。

2. **监督目标带有静态坐标偏差。**  
   在 `4d05/9069/cb78` 中，教师 t0 边偏差的 RMS 约为未来待修正边差异的 `1.06/1.01/0.99` 倍，方向余弦为 `0.96/0.99/0.98`。关系头容易学习到跨坐标链的静态偏移，而非未来形变。t0 位移锚定后结果有所改善，但只在 `1/4` 个视频同时优于 baseline。

3. **图积分不是瓶颈。**  
   直接使用真实未来边关系时，组件级 L2 积分误差接近 `1e-16`。误差主要产生于关系修正的预测和选择，而不是积分器不能恢复节点坐标。

4. **训练时能拟合，跨视频不能迁移。**  
   单视频和短时域中出现过局部改善，未见 query 或未见视频上没有稳定收益，说明当前 head 更像是在拟合训练视频/时间段的关系偏差。

## 仍需验证的因素

- 冻结的 `H` 是否缺少未来关系所需的物体级状态；
- 2D kNN 是否把不同深度层或不同运动部位错误连接；
- 边级目标的方差是否过高，导致逐边预测后经图投影放大误差；
- 训练损失与长期结构指标之间是否存在不匹配。

## 方法层面的解释

当前接口确实把点间关系送入了模型，但关系只在预测完成后作为“形状修正”使用，没有参与 MotionForesight 的未来轨迹生成。它假定：

1. `H` 已含有可迁移的关系信息；
2. 关系标签无明显坐标偏差；
3. 每个时刻都值得施加修正；
4. 逐边修正经过积分后仍然稳定。

F2 主要暴露了前两项和第三项不成立。因而“使用了关系”与“关系能够改善预测”之间存在明显差距。

## 建议的最小重设计

采用 baseline-preserving 的物体中心残差模型：

1. 用所有 query 的 `H`、观测期相对运动和当前 baseline 汇聚物体级状态；
2. 预测低维的共享物体运动/形变状态，再生成 query 级残差；
3. 同时预测对象级门控和边级可信度；
4. 通过组件级约束求解得到修正，但强制 `g=0` 时精确退化为 baseline；
5. 对修正幅度加入物体尺度归一化和保守正则；
6. 使用同坐标真实标签训练，优先优化最终 decoded coordinates，同时保留关系一致性损失。

这个结构保留软关系和形变能力，不引入固定刚体假设。它避免了独立边修正直接扩散到所有节点，也允许模型在无法判断时不修改 baseline。

## 后续裁决顺序

先比较：

1. baseline；
2. 带对象级门控的 node residual；
3. 对象中心状态 + 低维形变基的关系模型；
4. 仅在前两者显示收益后，再加入显式边积分。

若对象中心门控模型仍无法在独立视频上稳定改善结构指标并保持 raw ADE 不恶化，应放弃“冻结输出端后处理关系头”作为主接口，把关系建模移入可训练的预测模块。
