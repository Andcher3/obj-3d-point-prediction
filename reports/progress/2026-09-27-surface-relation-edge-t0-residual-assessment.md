# t0 边残差锚定的数学含义与既有实验

- 日期：2026-09-27
- 状态：ANALYZED；未运行新实验

## 数学上成立的版本

对固定、身份一致的 query 点 i、j，令观测期 TrackCraft 的三维边向量为 `eO0=O0[j]-O0[i]`，完整视频 TrackCraft 的三维边向量为 `eTt=Tt[j]-Tt[i]`。提出的 t0 残差修正可写为：

```text
e_target_t = eTt + (eO0 - eT0) = eO0 + (eTt - eT0)
```

它让标签的 t0 边等于观测期边，同时保留完整视频 TrackCraft 的边向量时间变化。若对各节点直接使用 `X_target_t[i]=O0[i]+Tt[i]-T0[i]`，每条边恰是上述结果，且天然满足点坐标可积性。它不保证这个合成未来就是真实未来，因为 O0 的误差会原样保留下来，完整视频 TrackCraft 的未来变化也可能有误差。

若“距离”仅指无方向的标量长度，`d_target_t=dTt+(dO0-dT0)`也满足 t0 的数值边界，但可能为负、违反多点三角关系，并无法表达相对方向。因此当前边向量预测与图积分应采用三维边向量，而不是直接对标量边长执行相同操作。

## 既有 F2 对照

`scripts/surface_relation_f2_observed_relations.py` 的 `anchored_displacement` 已做过节点等价实现：`gt=gt-teacher_t0+recorded_t0`。其输入仍包含 observed-only TrackCraft 历史，完整 TrackCraft 教师先经过 t0 全局相似变换；并非 DA3-only 的新路线。

四视频留出、五种子对照中，以锚定标签评价，baseline 的归一化去质心/边向量误差分别为 `.0359/.0324`；history 为 `.0664/.0544`，shared 为 `.0585/.0503`，safe 为 `.0707/.0545`。三种关系头各自只有 `1/4` 视频的两项指标同时优于 baseline。该结果说明静态 t0 差异可被移除，但移除差异未让现有关系头稳定获益；样本少，不能推及其他架构与 DA3-only 路线。

## 对跨运行误差的裁定边界

上述实现以每点三维坐标差构造标签，训练和评价的是三维边向量，并没有仅对标量边长做差。它精确消除两次运行在 t0 的点/边位置差异，留下完整视频教师的位移增量 `Tt-T0`。构造该目标完全不需要“只看过去”的运行产生未来轨迹；先前把缺少这条未来轨迹说成尚未排除的跨运行问题，是概念混淆，应撤回。只要同一 query 身份、t0 时间和三维坐标/尺度匹配，双运行在 t0 的静态偏移已经按定义消除。完整视频教师未来位移本身是否准确，属于普通伪标签质量问题；不能未经额外证据归因于两次运行不一致。

锚定目标下四视频留出表明：baseline 对三个视频的误差已经相对较低，仅 `6516` 视频的 history 版本同时改善两个指标；训练视频验证时门控全选 `1.0`，在另外三个留出视频造成过修正。这个结果直接支持现有 head 未学会跨视频判断何时、修正多少，不能将其唯一归因于教师未来位移、冻结特征或样本量。

## 更正上轮表达

先前建议直接在“最后观测帧的 DA3 pointmap”上以 frame-0 query 的原像素坐标采样，忽略了运动物体的跨帧 query 身份。MotionForesight 的 query 以 frame 0 为参考；若锚定时刻为最后观测帧，需要得到该时刻每个参考 query 的对应点。没有对应关系不能直接把相同像素当作同一点。可只用 frame-0 观测 pointmap 构造参考几何静态边特征，或在观测段取得可核验的跨帧对应关系。
